更新日期：2026-11-07。覆盖里程碑步骤 **S02–S19**。

本次交付把“日程”作为第三个入口接进现有客户端：月历、日详情、手动任务与个人占用、每周重复、冲突检查、单日休息、可用时间、本地确定性排课、排期草案预览／应用／撤销、AI 排课对话、计划材料目录、知识清单、教材会话恢复、每日课程阅读／作答／自检、学习记录、复习入口与补课建议。S20 的真实模型质量与 S21 的 Android 真机／发布验收仍未完成，不冒充通过。

### 1.1 手动路径

1. 从“日程”选择日期，点“新增安排”。
2. 填标题、日期、起止时间；可选计划、科目、学习方式、优先级、完成条件、知识点与教材页段。
3. 需要每周重复时打开开关，选择星期和结束日期；一次最多展开 366 天，超出会明确拒绝而不是静默截断。
4. 保存前检查时长、页码、计划归属与所有发生日期的冲突；冲突会指出日期、时间和已有任务，不覆盖旧安排。
5. 保存后立即出现在月历与日详情，重启后从 SQLite 恢复。

个人占用与学习任务分开：占用块没有任务内容，但同样参与冲突检查与排课避让。

### 1.2 学习状态

- “完成”记录实际完成分钟与时间；“部分完成”可多次累计，只增不减；“跳过”必须填写原因。
- 打开教材不自动记为完成；阅读器返回后仍停留在原日期与原月份。
- 完成、部分完成、跳过分别写入 `learning_records`，`operationId` 唯一约束阻止重复点击产生双份记录。
- 任务状态由时间块聚合：未开始、进行中、已完成、已跳过；逾期由当前时间派生，不写死为状态。

### 1.3 自动排期与撤销

1. 计划下先建立“待安排任务”（标题、预计分钟、学习方式、优先级、完成条件）。
2. 在“可用时间”确认每周时段、每日上限、机动比例、每周学习日、块间休息与学习单元。
3. “自动排期”只读生成草案：新增／移动哪些块、可用时间、实际安排、机动预留、未排入任务、警告与假设。
4. 点“应用计划”才写正式日历；应用后提示可撤销。
5. 撤销只对最近一次、且之后没有其他日程修改、相关块仍未开始时可用。

### 1.4 AI 排课路径

1. Win 端在日历下方弹出缩短的浮层对话框（340px、拖拽把手、遮罩、卡片形式，不覆盖侧栏，展开时不压缩日历，日历与右侧详情之间保留细分隔线）；手机端从底部浮起。右侧日详情可收起，收起后只有点击某一日才重新展开；点击月份标题打开年视图，按年切换并选择 12 个月。作用域是当前筛选的计划；没有筛选时是新计划。
2. 输入考试日期、科目、可用时间等目标。点“发送”先看到**发送预览**：本地日期、时区、作用域、将发送的消息、历史消息数量和模型；不发送教材原文或其他计划的任务标题。
3. 模型只允许返回四类结构化结果：
   - `clarification`：最多 3 个补问；可带候选选项。
   - `proposal`：计划字段与／或每周可用时间草案，附假设和未覆盖范围。
   - `answer`：只解释，不修改设置。
   - `insufficientMaterial`：列出缺少的材料。
4. 客户端校验日期真实存在、过去日期不静默顺延、计划引用只能指向当前作用域、时段在同一天且结束晚于开始、容量数值在范围内、字段在白名单内。
5. 草案以卡片展示；点“查看并应用设置”后再次确认。应用时在一个事务内写入计划与可用时间，并把对话绑定到新计划；**不会创建日历时间块**。之后仍需在计划里建立待安排任务并执行自动排期。
6. 生成中可以取消；取消或切换对话后，晚到回复不会写入消息，也不会修改计划。失败和取消都会作为消息保留，便于之后重试。

### 1.5 计划材料目录

1. 在“计划管理 → 材料”中把书库资料绑定到计划，选择用途（教材／考纲／真题／练习册／笔记）、可选章节名与物理页段。
2. 每段材料显示已解析页数、待识别页、待处理页、失败页与缺失页；只有已提交文字或 OCR 的页才算“已解析”，导入但未读取的页不会被说成已覆盖。
3. “补齐 N 页”只处理该页段中尚未就绪的页，串行调用现有本地文字提取／OCR；失败或 OCR 不可用时保留明确状态，可再次处理。
4. 资料删除或计划删除由外键级联解除材料引用；任务自身的教材页段快照仍然保留。
5. `MaterialCatalogService` 只读取已就绪页，跨文档输出带 documentId、hash、用途、页段和文本的分块，供 S12 提取知识点；不会在读取时隐式触发联网或 OCR。

### 1.6 知识清单与待安排任务

1. 在“计划管理 → 知识点”中从已解析材料提取，或手动添加知识点。生成前显示模型、材料分块数、覆盖页数与提取重点；确认后才联网。
2. AI 只能返回标题、目标、来源 chunkId、页内起止页、优先级、用时、活动类型、完成条件与前置下标；客户端拒绝未提交的 chunk、编造页、越界页、未知活动、超范围用时和引用自身的前置。
3. 知识点保存来源快照（documentId、hash、页段、原文摘要），打开原文可回查；材料删除后来源标示为已解除，不留下可点击的死链接。
4. 可编辑标题、目标、优先级、预计分钟、学习方式、完成条件与前置关系；保存时检查缺失引用、跨计划引用与循环前置。
5. “加入待安排任务”创建一条独立 `StudyTask`，保留知识点来源页段与完成条件，并写回 `taskId`；重复点击返回原任务，不复制。任务仍由本地排课器按时间与容量安排。

### 1.7 任务到教材与会话

1. 从日详情任务打开教材前，先校验 documentId、文件 hash 与页段；资料删除或版本变化时拒绝打开并说明原因，日历记录仍保留。
2. 任务按 documentId 保存 `readerSessionId`。打开同一任务时恢复该 session，而不是该文档“最近一次”的 session；日期 A 不会误入日期 B 的会话。
3. 保存的 session 缺失、所属文档不符或页段已改变时，新建 session 并更新绑定，不把旧进度冒充新页段。
4. 返回日程时仍选中原日期与月份，日详情保持原状态；打开教材本身不自动完成任务。
5. 一个任务当前绑定一份教材；多资料任务需要后续扩展为多组 page-range/session 映射，现阶段不会伪造其他资料引用。

### 1.8 每日课程与学习记录

1. 从日详情任务菜单“今日课程”生成课程；发送前确认模型、任务与教材页段，只发送这些已解析页。
2. 课程包含讲解、题目、最终答案和完整解答；答案默认折叠，用户必须先写草稿再展开。
3. 草稿与实际用时保存在本机 settings，不进入正式学习记录；关闭重开可恢复。
4. 自评“答对／需要复习”写入 `learning_records`，使用 operationId 去重；打开课程或展开答案不会自动完成任务。
5. 复习页读取 `review` 记录，卡片可回到原日期和课程；补课建议只使用计划可用时间和现有块，不改变每日上限或其他计划。
6. 课程缓存需匹配现存文档、hash 与页段；资料删除或页段变化后旧课程隐藏，历史课程行仍保留。

## 2. 数据与规则

### 2.1 v6 表

| 表 | 作用 |
| --- | --- |
| `study_plans` | 计划、考试日、状态、revision；JSON 保存目标与学习模式。 |

| `calendar_blocks` | 日期、起止分钟、类型、状态、锁定、系列 ID、`instanceKey`、revision；索引日期、计划、任务与系列。 |

| `knowledge_items` | 知识点：标题、目标、来源快照、前置 JSON、优先级、用时、活动、完成条件、关联任务与 revision；删除计划级联，删除任务时关联置空。 |
| `daily_lessons` | 每日课程版本：讲解、题干、答案、解答、来源页段、模型与状态；删除任务/计划级联，旧版本保留。 |

迁移前备份位于数据库同目录，命名 `study.sqlite3.v1-backup-<UTC 时间>`、`.v2-backup-…`、`.v3-backup-…` 或 `.v4-backup-…`，可直接用 SQLite 打开。`LocalStore.backupPaths` 返回本次启动产生的全部备份（旧→新），`lastBackupPath` 返回最新一份；新装库不生成备份。

### 2.2 排课约束

- 日期范围：不早于计划开始日，也不早于今天；不晚于计划结束日，且默认不占用考试当天。
- 时间：同一天内、结束晚于开始；不跨午夜。
- 容量：每周时段扣除其他计划占用、本计划锁定／已开始块后，再应用每日上限与机动比例。
- 优先级：重点 > 普通 > 可选；同级按任务创建顺序与稳定 ID。
- 拆分：可拆任务按学习单元切块，最后一块小于最小连续时长时并入前一块；不可拆任务整块放入空档。
- 周学习日：按日期先后选择；已达上限的日期不再增加新学习日。
- 机动时间只保留、不自动花掉；排不下时列出剩余分钟与原因。

### 2.3 AI 契约边界

- 模型不能创建、删除或移动日历块，不能声称计划已应用；只能提出设置草案。
- 模型不能引用当前作用域之外的计划 ID；不能编造教材章节、页码、分值权重、提分概率或掌握度。
- 没有材料或需要具体知识点内容时返回 `insufficientMaterial`；本版不生成章节正文或课程。
- 用户消息和历史都是数据，不是系统指令；请求不包含 API Key，密钥只由本机传输层附加。
- AI 不设置单日例外（休息日仍由用户在日详情里手动设置）；不改变每日上限之外的其他计划。
- 每条消息的失败／取消状态直接记录在 `planning_messages`；独立 `GenerationJob` 表尚未建立，取消后晚到回复由控制器 generation 令牌丢弃。

### 2.4 不可变事实

- 改期不换 `taskId`；重复系列的 `instanceKey` 保持原计划日期与序号。
- 已完成／已开始块不会被自动排期移动，也不会被“这次及以后”批量改写。
- 计划删除会级联删除其任务、时间块、可用时间、排期修订、排期对话与材料引用；学习记录保留，便于审计。
- 删除教材会级联解除 `plan_sources` 引用；任务自身保留“教材已删除”标记与原页段，打开入口禁用；任务文字、日历与学习记录保留。

## 3. 尚未实现

以下属于计划的 S20–S21 和仍需人工验收的部分：

- 真实模型生成计划、知识点、课程的质量与费用抽检（S20）。
- Android 真机上的键盘、返回、日期触控与课程作答验收。
- 系统通知、ICS、时区/DST、跨午夜等未接入能力。
- 取消/中断后的完整恢复走查（当前失败生成不会写入课程，但缺少生成中的取消按钮）。
- 系统通知、闹钟、ICS、系统日历同步、跨设备同步。
- 时区换算与夏令时不存在／重复时间的交互选择；当前只保存时区名称，排课按设备本地墙钟分钟计算。
- 跨午夜安排；当前直接拒绝跨天时间块。
- Android 真机交互验收、Windows 完整窗口端到端走查、真实服务商排课质量抽检。

这些缺项不会被“构建成功”或“自动化通过”替代。真实模型能否按协议返回合格草案，仍需在 S20 用用户配置的模型和真实材料抽检；当前测试只验证协议、校验与本地状态。
