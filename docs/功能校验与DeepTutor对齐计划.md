## 已复现的问题

### F01　论文导读会漏掉后文证据　P1

位置为 lib/app_controller.dart 的 evidenceFor 与 _boundEvidence，约第 476–554 行。所有任务共用最多 10 个片段、16,000 字符的选择逻辑。问题无匹配时退回当前页及范围内靠前的片段。论文导读入口虽然选择整篇页段，也仍走这条路径。

复现时第一页放 12 段英文背景，第二页放局限段，使用中文导读指令。实际请求选到的 10 段全部来自第一页，第二页局限未进入请求。此时模型给出“本文未说明局限”可能只是没检索到，使用者难以辨别。

修复应按任务取证。导读先建立章节和页段覆盖表，再分别提取问题、方法、结果及局限，每个摘要保留原文 ID，最后合成导读。将“资料未说明”“相关页尚未解析”“检索未找到”作为三个结果状态。验收需包含只在末页出现局限、不同章节矛盾、跨页表格及中文提问英文资料。

### F02　追问无法自然承接上一轮　P1

位置为 lib/services/ai_gateway.dart 约第 449–452 行。请求固定只有 system 与当前 user 两条消息，controller 保存的历史没有进入后续请求。

探针先完成一轮问答并验证历史已保存，再问“用简单的话解释刚才那点”。下一次 payload 仍只有两条消息，既无首轮问题也无上次回答。增加本地历史展示不能解决这个问题。

修复需建立 conversation_id 和 turn_id，将当前学习小节、最近若干轮、压缩后的早期摘要与本次原文证据一起组成预算内上下文。摘要记录其覆盖的消息范围和版本，原文引用继续指向证据快照。跨文档或切换学习会话时显式改变作用域。新增历史内容也要进入发送预览。验收覆盖指代追问、重启续聊、切换论文、修改旧问题、长会话截断及取消发送。

### F03　证据不足的回复会被写成正式练习　P1

位置为 lib/app_controller.dart 约第 644–684 行。send 保存 insufficientEvidence 后，出题与评阅分支仍按任务类型推进 session。

探针令出题接口返回“Missing source. Please select pages.”且 insufficientEvidence=true，结果 session.stage 变为 question，该提示成了练习题。评阅分支也需要同类防护。

修复应让结构化结果通过校验后才能改变学习状态。出题结果至少包含题干、题型、知识点、证据和独立保存的评阅依据。证据不足、协议错误、取消、超时均保留已有进度并给出可执行的补救步骤。对重试使用任务 ID 防止重复新增题目或作答。验收包括出题失败、评阅失败、切换会话后晚到的结果和重复提交。

## DeepTutor UI 观察

本轮同时查看了 DeepTutor 1.7.1 的本地 Web 界面。它的功能组织很完整，但导航与能力入口非常密：Home、Learning、Resources、Partners、Personalization 并列，每项能力都配有说明文字和入口卡片。作为产品调研这很清晰，照搬到 Quelyt 会让日常阅读界面变成功能目录。

Quelyt 因此只保留 **书库 / 复习 / 设置** 三个目的地；去掉页面大标题区、`工作区` 小标签、`本机` 状态胶囊、空状态说明段落和重复的隐私声明。隐私与发送规则集中在设置页，用短句表达。DeepTutor 的广度继续作为功能路线参考，不作为界面文案模板。

### 应先固定的数据与接口契约

- 消息保存 conversation_id、turn_id、task_id、状态、关联证据快照、模型与用量。已显示的部分输出和已完成响应分别记录，取消后由明确状态恢复。
- 学习计划保存章节与知识点 ID、来源、前置项、目标能力、下一活动。重新生成提供差异，已作答节点继续关联原记录。
- 题目保存知识点、类型、难度、题干、答案或评分规则、证据、生成模型版本。作答与每次评阅另存，重评可追踪。
- 评分返回逐要点满足情况、错误类型、证据支持、置信状态和建议动作。资料不足与模型无法判断保持待核对状态，用户可以推翻评阅。
- 掌握记录保存观测依据和时间。点击读完、用户自评、完成一道题分别标记来源，到期复习策略可解释并可重新计算。
- 证据保存原件哈希、解析版本、物理页、区域和文字或图像来源。OCR 校正更新索引，历史已发送快照保留当时内容。
- 将检索、读取原页、读取图表、生成题目、评阅实现为可记录输入输出的工具。每个工具限制材料范围、页数、调用次数和预算，使学习代理能补查证据并说明失败位置。

### 验收数据与指标

固定一套有权使用的资料和人工答案，再让 Quelyt 与 DeepTutor 使用相同文本模型、视觉模型及可比预算。记录各自解析、检索、最终答案和实际费用。分开统计材料读错、证据没召回、模型推理错误和引用绑定错误。

| 测试集合 | 推荐门槛 |
| --- | --- |
| 连续学习 | 10 组五轮追问，至少 9 组正确承接指代与学习目标；切文档用例全部保持作用域正确。 |
| 导读覆盖 | 至少 10 篇含不同章节结构的论文，人工标出关键证据页。必须输出解析覆盖状态，已提供且完成解析的局限页进入相关取证。 |
| 检索 | 建立至少 60 道中英文问题，标注目标页与段。记录 Recall@10、引用支持率和无答案识别，优先提高召回再调提示词。首轮目标 Recall@10 ≥ 90%。 |
| OCR | 每端至少 20 页清晰印刷体与 10 页复杂页，分别记录中文/英文 CER、公式符号错误、表格单元格对应错误。清晰正文 CER 目标 ≤ 5%，复杂页单独报告。 |
| 学习状态 | 拒答、超时、取消、重复点击、切会话、重启和重评各有用例，错误结果不推进题目或掌握状态，历史尝试不丢失。 |
| 性能 | 200 页扫描本与高像素照片实测首屏、当前页 OCR P90、峰值内存和后台任务响应。沿用首屏 3 秒、OCR P90 10 秒目标，附设备型号和结果分布。 |
| 数据与费用 | 预览与发出的证据/图片一致，重试不扩大授权范围。每次任务记录输入输出用量及失败情况，导出恢复后原页引用可用。 |

## 调研环境与复现

DeepTutor 调研使用独立的本机 Python 环境，安装 PyPI `deeptutor[full]==1.7.1`，本地 Web 端口为 `3782`，后端端口为 `8001`。调研环境、运行数据和本机启动记录不随 Quelyt 源码归档。

Quelyt 的补充探针可用工作区 Flutter 执行 flutter test --no-pub .tooling/function_audit_test.dart，输出在 .tooling/function-audit-probes.log。探针使用内存数据库和合成资料，适合复现上述三处逻辑缺口。正式修复时应将其改为正确行为的回归用例，纳入 test 目录。
